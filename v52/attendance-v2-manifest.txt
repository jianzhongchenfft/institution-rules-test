Attendance V2 runtime architecture
Date: 2026-10-07

Authoritative runtime files:
1. attendance-v2-core.txt
   - lifecycle registry / shared UI hooks
2. attendance-v2-overtime.txt
   - overtime application / approval
   - comp leave ledger / use / expiry
   - regular-day warning
   - approved-record adjustment
   - manager leave balance
3. attendance-v2-payroll.txt
   - wage basis
   - overtime pay calculation
   - payroll settlement / correction
4. attendance-v2-annual-1.txt
5. attendance-v2-annual-2.txt
6. attendance-v2-annual-3.txt
   - the three annual fragments are concatenated in order and evaluated once
   - annual leave request / approval / cancellation
   - automatic anniversary entitlement
   - annual leave ledger / expiry / carryover
   - manual annual-leave credit creation has been removed

Architecture rules:
- part07 is the single Attendance V2 loader.
- Attendance V2 runtime uses no MutationObserver.
- Attendance V2 runtime modules do not fetch other Attendance modules.
- Legacy attendance patch files are retained only in backup branches, not in main.
- Staff hire_date is the single anniversary-cycle source.
- Database function private.staff_anniversary_period is the single anniversary-period calculation.
- Normal annual leave credits are system-generated; carryover credits are created only by the expiry/carryover workflow.
- Comp leave and annual leave keep separate ledgers; they share the anniversary-cycle source, not balances.
- Ordinary and holiday-visit comp leave use independent leave_type credit, pending, and usage balances; one usage never mixes the two.
- Usage defaults to ordinary and can be changed to holiday_visit before submission.
