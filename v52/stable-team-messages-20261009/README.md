## 恢復與版本比對程序

1. **先確認目標環境**：測試版與正式版的 GitHub／Supabase 必須分開；此處內容僅為測試環境的基準，不能直接套到正式版。
2. **前端恢復**：先建立工作分支，從本穩定分支取回 `index.html`、`v51/part07-clean.txt`、`v52/team-messages.txt`，再檢查三層版本載入網址及 JS 語法。僅在確認後部署。
3. **資料庫比對**：在目標測試 Supabase 執行本資料夾的 `verification.sql`，與 `database-catalog.json` 比對；實際授權以當下資料庫為準。
4. **回到安全的 V36 存取模式**：若只有 INSERT 權限漂移，先審核並視需要套用 `team-message-insert-access-v36-20261009.sql`；另外確認 `authenticated` 對 `team_message_favorites` **僅有 SELECT、INSERT、DELETE**，若恢復多餘權限則撤銷 `TRUNCATE`、`TRIGGER`、`REFERENCES`。操作前請再次確認權限相依。
5. **函式或 RLS 邏輯偏離基準**：比對指紋，找出改動來源及相對應的版本遷移檔，先在測試環境修復。由於未保存完整資料庫 DDL／資料備份，**不可僅憑指紋直接重建函式或 RLS**。
6. **重新回歸測試**：使用受權登入身分，確認建立訊息、追加分工、通知未閱讀、執行困難、回報、結案及重新開啟正常；使用交易回滾避免留下測試資料。
